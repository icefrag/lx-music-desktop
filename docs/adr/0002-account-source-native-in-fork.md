# 0002 - 账号音源原生集成，不走 userApi 脚本

日期：2026-10-13 ｜ 状态：Accepted

## 背景

免费音源（野花/野草等）本质是匿名第三方中转，不稳定、音质差，是用户的主要痛点（要的是「稳定能下到歌」，音质不设契约）。用户持有酷狗/QQ/网易云三平台会员，希望用自己账号解析链接。

生态标准形态是 userApi 脚本，但 lx 音源沙箱有硬限制：

- 唯一出网通道 `lx.request`，无持久存储（切换音源即清空）；
- 脚本不能打开任何窗口/导航 → 无法实现「登录后自动抓 cookie」；
- 解析单次 20s 超时；跨源兜底在脚本形态下不可能。

用户拥有本 fork，且 cookie 过期后手工维护脚本被用户明确拒绝（Q5）。

## 决策

把「账号音源」做成 fork 内置功能，而非脚本：

1. 设置页给酷狗/QQ/网易各一个登录入口 → 应用内打开平台官方登录页（`persist:` session 分区，支持扫码），登录成功后经 `session.cookies` 自动抓取凭证，持久保存在分区里。
2. 解析逻辑在主进程实现（Node 原生 crypto，无沙箱/超时限制），按平台使用对应 cookie 直连官方客户端接口。
3. 插入点在渲染进程 `api-source` 的 musicUrl 路由之前：账号音源优先，失败自动落当前生效音源（兜底链），再失败才报错。
4. 凭证状态三态（未登录/正常/已过期）在设置页展示；检测到过期时 toast 提示，并经开放 API 可查询——用户要求「告诉我哪个 cookie 过期了」。

## 备选

- **纯 userApi 脚本（+ cookie 采集工具）**：可发布给原生 lx 用户，但 cookie 过期需重新生成并导入脚本、无兜底链、受 20s 超时与沙箱限制 → 用户拒绝。
- **本地辅助服务 + 薄脚本**：同样要做一个登录采集 UI，还多一个常驻进程；对本用户（fork 所有者）没有额外收益。

## 后果

- 功能 fork 专属，原生 lx 无法使用（可接受：用户日常与 OpenAPI 消费方都用本 fork）。
- 平台接口为非公开客户端接口，可能随平台版本变动；用自己账号有风控风险（用户已知悉并接受）。
- 酷狗凭证与签名链路最复杂，风险最高，放最后实现（顺序：网易 → QQ → 酷狗）。
- cookie 服务端失效无法从 cookie 元数据察觉，需以「轻量校验接口 + 解析失败反馈」判定过期。
