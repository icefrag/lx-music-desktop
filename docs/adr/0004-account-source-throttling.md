# 0004 - 账号音源请求节流：平台队列 + 风控冷却 + 单平台下载并发

日期：2026-10-13 ｜ 状态：Superseded by [0005](0005-download-resolution-channels.md)（队列与风控冷却仍有效；「单平台 1 个任务」已被解析级限速取代，「0 为不限速」已改为下限 1s）

## 背景

批量下载时账号解析请求无节流：全局「同时下载任务数 3」下，3 个同平台任务并发解析、每首 1-2 发请求，短时间内几十发就把酷狗账号打到风控限流。实测触发因素排序：并发突发 > 持续频率 > 总量。平台阈值是黑盒，无官方文档。

## 决策

节流**只作用于账号链路生效的平台**；账号未登录/已过期/冷却中的平台走免费源，只受全局同时下载数约束。

1. **每平台请求队列**（主进程 `accountSource/queue.ts`）：同平台播放/下载/开放 API 的解析请求串行过单一闸口，按平台最小间隔放行（默认 酷狗 8s / 网易 3s / QQ 3s，±20% 抖动打破机器节奏）。间隔进设置页（`accountSource.requestInterval.{kg,tx,wy}`，0 为不限速），主进程实时读取。参数是保守起步值而非算出的最优值——配观测反馈调（还触发就加大，一周不触发可调小）。
2. **风控冷却**：平台返回风控信号（酷狗安全验证等，抛 `RiskControlError`）→ 该平台冷却 10 分钟起步，连续触发指数翻倍（上限 1 小时），成功一次复位。冷却期请求快速失败（不占队列不碰平台），渲染层兜底链自动接管。
3. **单平台下载并发**：账号生效的平台同时只跑 1 个下载任务（渲染进程 `getStartTask` 按来源计数），治并发突发；免费源任务不受限。

## 备选

- **多账号轮换（账号池）**：改动大；且若平台按 IP 记风控，轮账号无效 → 拒绝，先做节流。
- **只在下载调度层限并发、不做请求队列**：风控看的是请求频率不是并发数，播放/开放 API 路径同样打平台，必须收敛到单一闸口 → 并发上限只作辅助。
- **自适应间隔（AIMD）**：没有一周量级的观测数据前是过度设计 → 拒绝，冷却机制已覆盖激进行为。
- **播放请求插队**：需要把优先级标记穿透渲染层→api-source→主进程三层，代价大于「播放最坏等一个间隔周期」的收益 → 拒绝，体验不满再补。

## 后果

- 同平台批量下载吞吐 = 1 首 / (间隔 + 下载耗时)（酷狗 100 首约 40-60 分钟），批量场景可接受，交互场景（听歌）无感。
- 节奏参数未经验证，依赖诊断日志的观测反馈做第二轮调参。
- 风控信号目前仅酷狗明确（安全验证），网易/QQ 的风控形态未知，遇到再补抛 `RiskControlError` 的点位。
