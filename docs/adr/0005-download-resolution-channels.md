# 0005 - 下载解析通道模型：解析级限速 + 双通道平级分发

日期：2026-10-14 ｜ 状态：Accepted

## 背景

0004 的「单平台同时只跑 1 个下载任务」把风控保护扩大到了 CDN 下载阶段（直链下载不碰账号接口），同平台吞吐 ≈ 1/下载时长；且 tx 频率风控呈时间窗波动（issue 02），冷却 10min-1h 期间任务只能干等。用户实际只下载 128k，内置音源野花恰好全平台仅提供 128k——第三方通道对用户没有音质成本。2026-10-14 上午已实施解析级限速（取代任务级串行，见 plans/01）。通道策略经两轮设计评审：初稿「账号优先 + 冷却溢出」被用户否决，定为双通道平级分发。

## 决策

**账号音源与三方通道平级常开，下载解析按可用性分发。**

1. **解析级限速**（已实施）：同平台下载并发放开，账号解析由主进程队列串行 + 平台间隔（kg 8s / tx 5s / wy 3s，下限 1s，±20% 抖动）+ 风控指数冷却保护。取代 0004 第 3 条。
2. **双通道平级分发**：下载解析入口为分发器——账号音源与三方通道（内置野花脚本）谁先空出来谁服务；同时可用优先账号（官方直链优先）。两通道按各自节奏自然放量（账号 5s、野花 2s，大批量时野花约承担 70% 流量）。
3. **失败互换**：任一通道解析失败自动换对侧重试一次；对侧也不可用再走兜底链（当前生效音源，若生效音源即野花则跳过）。
4. **质量门槛**：野花仅服务 `quality == '128k'` 的任务；flac/320k 任务仅走账号，账号冷却时保持等待（自动恢复机制不变）。
5. **三方通道基建**：主进程常驻第二个 user-api 沙箱页固定加载野花，与当前生效音源无关；独立节流（串行 2s）与熔断（连续失败 3 次停用 5 分钟，期间流量全量走账号）；经野花解析的任务状态文本标注「已用三方源(野花)」。
6. **播放链路不变**：账号失败（含风控）即时回落当前生效音源。下载与播放行为不同是有意的。

## 备选

- **账号优先 + 仅冷却溢出**（本 ADR 初稿，同日被否）：对 128k-only 用户没有音质收益，却放弃了日常分摊的提速、账号请求减负（→ 风控窗口更少的良性循环）与野花健康度的持续探测 → 否。
- **机械 50/50 轮转**：为「公平」让野花空等账号，解析节奏反而慢于可用性优先 → 拒绝。
- **野花优先、账号兜底**：与可用性分发等价但更差（无视账号先到先得的官方直链）→ 被分发器 tie-break 吸收。
- **野花/野草同时生效的多音源模型**：沙箱、设置页、开放 API 枚举全要动；野草仅酷我 128k，对 kg/tx/wy 下载无增益 → 拒绝。

## 后果

- 大批量 128k 下载解析节奏 ≈ 1.4s/首（纯账号 5s），日常约 70% 文件来自野花上游——其 128k 码率不保证与官方一致（兜底链「音质不设契约」原则的延伸，用户已知悉并接受）。
- 账号请求量降至约 1/3，风控窗口本身减少；两通道互为对侧，任一方故障自动全量切另一方，最坏退化到纯账号吞吐（即现状）。
- 主进程多一个常驻沙箱页（内存 ≈ 一个隐藏页面）；野花脚本随应用分发升级。
- 用户侧可感知：部分任务标注「已用三方源(野花)」。
