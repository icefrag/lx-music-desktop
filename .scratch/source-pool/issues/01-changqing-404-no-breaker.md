# 01 - 长青大量 404 下载错误且熔断未触发

**类别**: bug ｜ **反馈人**: wuirui ｜ **日期**: 2026-10-15

## 反馈原话

使用时长青出现大量 404 的下载错误，但是没有触发熔断。看看为什么 404，为什么没触发熔断。如果确定长青不可用于下载，就去掉这个来源。404 应该触发熔断，这个必须加上。

## 核实结论（2026-10-15）

### 为什么 404

长青是「模板源」：脚本把 `http://yinyue.haitangw.net/<platform>/*.php?type=mp3&id=<id>&level=standard`
拼出来直接返回，不验证可用性。2026-10-15 现场复探（带 UA）：

- `wy.php?id=186016`（晴天）→ **404 nginx**
- `qq_kw.php?id=0039MnYb0qxYhV`（晴天 tx）→ **404 nginx**
- `kg.php` → **404 nginx**

上游 `yinyue.haitangw.net` 的解析服务已死，三个平台全灭。真机「大量 404」与此吻合
（此前播放成功属上游半活期）。**结论：长青不可用于下载，移除。**

### 为什么熔断没触发（设计盲区，非意外）

1. **解析层**：脚本成功返回 URL 模板 → 池认为成员健康，failCount 归零。熔断只监听
   解析层信号（ADR 0006 已知边界：「下载层失败不回灌熔断」）。
2. **下载层**：worker `onFail` 里 404 不在换链名单（仅 401/403/410 → refreshUrl），
   404 走 default 同 URL 盲试 3 次（模板 URL 必然次次 404）后报
   `download_status_error_response(404)` 终止。池全程无感 → 长青持续接活。
3. **附带发现**：`handleRefreshUrl` 绕过分发器直连生效音源（`getMusicUrl`），
   双通道/池化后未同步，换链结果不经过池与账号。

## 修复方案（已确认）

1. **移除长青**：config/index.ts 删条目 + `ensureBuiltinUserApis` 增加 prune
   （store 里 `user_api_builtin_*` 不在现行清单的删除，防僵尸内置被新防删守卫卡死）+
   渲染层 BUILTIN_MEMBERS 删行 + ADR/plan/词汇表同步。
2. **下载成败回灌熔断（反馈人强制要求）**：metadata 增 `poolMemberId`（tryPool 成功写入，
   getUrl 入口清空避免误记）；worker 回调 `complete` → 成员记账成功归零，
   `error`（排除写盘/路径类本地故障）→ 成员 failCount++ 走既有升级熔断。
3. **404 进换链名单**：worker `onFail` 404 与 401/403/410 同走 refreshUrl（同 URL 盲试
   对模板死链无意义）。
4. **refreshUrl 走分发器**：handleRefreshUrl 改用 `getUrl(downloadInfo, true)`，
   换链结果重新享受 账号↔池 分发与兜底链。
