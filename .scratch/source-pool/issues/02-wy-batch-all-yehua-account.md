## 反馈原话

提交了一批网易音乐的任务，但下载完成的记录全部用的是野花和账号音源。不是应该其他的几个三方音源也会加入吗？

## 核实结论（2026-10-15，dev 日志 + 端点复探）

### 幻音/全豆要确实被分发器选中过——但它们的链接死在下载阶段

1. dev 日志只见主进程错误：`spill_url Fail`（池成员）×N 全部是野花上游返回
   `msg='Fail'`（四个内置脚本均无 'Fail' 字面量，解析期真正发网络请求的只有野花）；
   幻音 wy/tx/kw 是纯模板构造（错误文案全中文），不可能产出 'Fail'。
2. 幻音模板构造不可能解析失败 → 若被选中必返回直链。而直链域名
   `music-dl.sayqz.com` **DNS ENOTFOUND**（2026-10-14 首探、10-15 复探均死）→
   链接必死在下载阶段。
3. worker 对 ENOTFOUND 走 refreshUrl → 换链重新分发 → 野花/账号交付 → 任务完成。
   **完成记录标注的是换链后的最后交付者**（getUrl 入口清旧标注），幻音/全豆要的
   首选痕迹被覆盖 → 用户看到「全是野花+账号」。

### 端点现状（2026-10-15 复探）

| 成员 | 端点现状 | 结论 |
|---|---|---|
| 幻音 | music-dl.sayqz.com DNS ENOTFOUND | wy/tx/kw 全死，mg 通道在当前分发下不可达（mg 不走池）→ **移除** |
| 全豆要 | kg.php 200 JSON 活；qq.php(tx) 403 octet-stream 门禁；wy/kw.php 404 死 | **保留但能力表收窄为 kg/tx**，其余平台不再接活 |

### 附带发现：换链失败不记账（熔断盲区之二）

worker 对 ENOTFOUND/403/404 走 refreshUrl 时不产生 error 事件 → 下载回灌记账
（issues/01）捕捉不到 → 死链成员永远「解析健康」反复被选中。补：refreshUrl 前
按当前 `poolMemberId` 记一次失败，随后 getUrl 入口清标注、重新归因。

## 修复方案

1. 移除幻音（config 条目，store 由既有 prune 清理；BUILTIN_MEMBERS 删行）
2. 全豆要 BUILTIN_MEMBERS 平台收窄 `['kg','tx']`
3. worker 回调 `refreshUrl` 分支：换链前对当前 poolMemberId 记一次下载失败
