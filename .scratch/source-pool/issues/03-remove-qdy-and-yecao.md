## 反馈原话

删掉内置的全豆要音源。同时确认一个事，野花 野草是不是同一个东西啊，如果是保留一个就行。我看现在基本都走其中一个。

## 核实结论（2026-10-15，脚本快照解码比对）

对 `config/index.ts` 里三个内置源的 `gz_` 脚本快照做 inflate 解码 + 字符串清单比对
（临时工具 `.scratch/source-pool/scripts/decode-builtin.cjs`，可复跑）：

**野花 ≡ 野草：同一后端服务的两个入口，非独立上游。**

- 两个脚本为同一套 javascript-obfuscator 混淆模板（同款轮转数组 + hex 字符串 +
  控制流平展，函数骨架逐段对应）；
- 后端同为 `http://97.64.37.235/`（两脚本字符串表均含 `http://97.` + `64.37.235/`，
  无第二个 IP）；
- 仅路径命名空间不同：野花 `flower/v1`（`/flower-source-info/…`），野草 `grass/v1`
  （`/grass-source-…`）；更新镜像串也只差 flower/grass 词根（`js.org/flo…wer` vs
  `js.org/gra…ss`）；
- 能力声明不同：野花 kw/wy/mg/kg/tx 全平台 128k；野草仅 `kw|128k`——与
  `spillChannel.ts` 静态能力表一致。

同一服务器 ⇒ 两者之间没有真实冗余（服务器挂则同时死），野草只是多占一个成员名额
与一份沙箱。用户观察「基本都走野花」与代码一致：默认音源、SPILL_API_ID、五平台
能力都是野花，野草只能接 kw。

**全豆要**：issues/02 已实测后端（kg 活、tx 403 门禁存疑、wy/kw 404 死），能力表
已收窄 kg/tx。维护者决定整源移除，kg/tx 由野花覆盖。

## 修复方案

1. `config/index.ts` 删 `user_api_builtin_yecao`、`user_api_builtin_qdy` 两条目 +
   头注释同步（store 残留由既有 prune（`ensureBuiltinUserApis`，issues/01 引入）
   随升级清理）。
2. 渲染层 `spillChannel.ts` BUILTIN_MEMBERS 删两行。
3. `defaultSetting.ts` 出厂别名 `yecao` 重映射到 `user_api_builtin_yehua`（同一
   后端，开放 API 老调用方 `set=yecao` 无感继续可用）。
4. ADR 0006（成员资格、后果冗余表）与 CONTEXT.md「音源池」词条同步。

已知共享边界（非本次修复，与长青/幻音移除同一条路径）：若用户曾把被移除内置源设
为生效音源，升级后 `common.apiSource` 指向已 pruned 的 id，启动时脚本加载不就绪，
需在设置里手动另选——`setUserApi` 的 catch 兜底只覆盖加载失败，不覆盖 id 不存在
（main `setApi` 静默 return）。
