# 方案 02 - 双通道平级分发：账号音源 + 内置野花

Status: implemented (2026-10-14，双端编译通过；主进程仅剩 tx.ts/kg.ts 在途改动的 5 个既有类型错误，与本方案无关。真机验收未跑，见「验收标准」)

## 行为契约（决策汇总，全部已确认）

- **双通道常开**：下载解析入口是分发器——账号音源与三方通道（内置野花，全平台 128k）谁先空出来谁服务；同时可用优先账号（官方直链 tie-break）
- **失败互换**：任一通道解析失败自动换对侧重试一次；两侧都失败走兜底链（当前生效音源；生效音源即野花时跳过，避免重复）
- **质量门槛**：野花仅服务 `quality == '128k'` 任务；flac/320k 仅走账号（冷却时 WAITING，现有自动恢复不变）
- **三方通道节流**：渲染层独立队列，串行 + 2s 间隔；**熔断**：连续失败 3 次停用 5 分钟，期间流量全量走账号
- **可见**：经野花解析的任务状态文本「已用三方源(野花)」
- **不迁移**：每次解析独立分发，不切回不重下；无设置页开关
- **播放不变**：即时回落当前生效音源（含风控），不等冷却
- **野草不动**：仅酷我 128k，与 kg/tx/wy 下载无关

## 单首歌曲的完整生命周期（128k tx 歌，账号已登录，批量中）

1. **创建**：点下载 → worker 生成任务（id / quality=128k / source=tx / 钉 apiSource）→ 去重入列表 WAITING → 触发调度
2. **调度**：`getStartTask` 只看全局并发 < maxDownloadNum(3)——平台冷却不再拦 128k 任务（分发器会路由）；任务 RUN
3. **分发**：解析请求进分发器——
   - 账号可用（未冷却）且野花可用（未熔断）→ **优先账号**
   - 仅一方可用 → 用可用方（账号等自身间隔、野花等 2s 节奏）
   - 双方都忙/不可用 → 排队等先空出来的一方
4. **解析**：
   - 账号通道：主进程 `requestUrl`，平台队列串行 + tx 5s±20% 间隔 → 签名通道 → 官方 128k 直链
   - 野花通道：主进程常驻野花沙箱 → flower 接口 → 128k 直链（2s 节奏）
5. **分支 A｜解析成功**：URL 写入任务（野花来源则状态「已用三方源(野花)」）→ worker CDN 下载（同平台并行）→ 写 ID3/歌词 → COMPLETED → 调度器拉下一个
6. **分支 B｜解析失败**：自动换对侧重试一次（128k 任务）；对侧也不可用 → 兜底链（生效音源非野花时）→ 仍失败 → ERROR（风控特殊：任务回 WAITING 等冷却/熔断结束自动重试）
7. **flac 任务特例**：只走账号；冷却时 WAITING 显示「风控冷却中，剩余 X 分钟」，冷却结束自动恢复

**批量效果**：10 首 tx ≈ 账号 2 首（0s、5s）+ 野花穿插（2s、4s…）交错完成，解析不再是瓶颈；下载全程并行。

## 实施项（总 ~5h）

1. **主进程：三方通道沙箱**（~2h，主要风险点）：常驻第二个 user-api 隐藏页固定加载 `user_api_builtin_yehua`（复用 `src/main/modules/userApi/renderer` 沙箱模式），暴露定点 IPC（如 `account_source_spill_url`：source/type/musicInfo，错误复用 risk_control 前缀约定）；与当前生效音源沙箱互不影响
2. **渲染层：分发器**（~2h）：`getUrl` 重构为「分发器 → 失败换对侧 → 兜底链」；野花侧节流+熔断器（模式同 queue.ts，渲染层实现）；`canStartByCooldown` 调整为仅拦 flac/320k；状态文本（「已用三方源」「冷却剩余」「解析排队」）
3. **验证**（~1h）：typecheck + 真机验收

## 验收标准

1. 大批量 128k：双通道交错放量（日志可见账号 5s / 野花 2s 节奏），解析节奏 ≈1.4s/首，野花任务带「已用三方源(野花)」标注
2. 同时空闲时优先账号（官方直链）
3. 野花熔断（连败 3 次）→ 全量回账号，行为等于纯账号；5 分钟后自动恢复试探
4. 账号冷却 → 128k 全量走野花（2s/首），flac 任务保持 WAITING 且冷却结束自动恢复账号
5. flac 任务任何情况下不从野花拿链接
6. 播放同一首歌：账号失败立即回落生效音源出声，不等任何通道
7. 播放/生效音源解析不受野花沙箱影响（互不干扰）

## 已知边界

- 野花 128k 为第三方上游，码率不保证与官方一致（已接受）
- 日常约 70% 流量压在野花：2s 间隔是礼貌上限，其上游限流表现为失败时熔断自动兜住
- 分发器让「冷却」对 128k 批量近乎无感——账号指数冷却的 protects 依然有效（账号请求量本身降到 ~1/3）
