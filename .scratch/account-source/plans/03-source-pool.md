# 方案 03 - 音源池：三方通道多成员化

Status: implemented（2026-10-14，双端 + user-api-preload 三构建目标全过，改动文件 eslint 干净（action.ts 344 行 require-atomic-updates 为 HEAD 存量）；真机验收未跑，见「验收标准」）

## 行为契约（决策汇总，全部已确认）

- **成员资格**：内置（野花、野草、长青SVIP、幻音、全豆要聚合）+ 用户导入的全部自定义源脚本，导入即入池、删源即出池；成员平等，无设置 UI
- **范围**：仅下载解析；播放一字不改（即时回落生效音源）
- **质量门槛**：池仅服务 `128k`；flac/320k 仅走账号，冷却时 WAITING 不变
- **选择**：按（平台 × 128k）能力过滤 → 健康成员中在途最少者；账号与池同时空闲优先账号
- **失败转移**：池内最多尝试 2 次（初始 + 转移 1 次）→ 账号 → 兜底链（跳过本次已试成员）→ 换源
- **熔断**：每成员独立，一切失败计数，连败 3 → 停 5 分钟；反复熔断时长指数升级（5→10→20→40→60 分钟封顶），任一次成功归零；不自动移出池（删源是唯一出池入口）
- **节流**：每成员独立串行 + 2s 间隔
- **沙箱**：每成员独立隐藏页，懒创建 + 空闲 10 分钟销毁
- **内置管理**：同野花/野草——可删、重启复原、无 UI；脚本 gz_ 快照随发版，无运行时远程拉取
- **可见**：状态徽标「已用三方源(<成员名>)」；健康状态仅日志

## 单首歌曲的完整生命周期（128k tx 歌，账号已登录，批量中）

1. **调度**：不变——全局并发 < maxDownloadNum(3) 即 RUN（128k 不受平台冷却拦截）
2. **分发**：分发器先账号/池平级竞争（同时空闲优先账号）；池侧从「固定野花」变为「选成员」——按 tx × 128k 过滤出健康候选（账号冷却时流量自然摊向全池）
3. **解析**：选中成员走独立沙箱（懒创建，init 后上报该成员平台×音质能力表）+ 独立 2s 节流队列 → 直链
4. **成功**：URL 写任务，徽标「已用三方源(<成员名>)」→ CDN 下载（解析成功 ≠ 直链必活，下载失败走现有重试/报错，不回灌熔断）
5. **失败**：换下一个健康池成员重试一次（总池尝试 ≤2）→ 账号 → 兜底链（生效音源，跳过已试成员）→ 换源 → ERROR；风控仍回 WAITING 等恢复
6. **成员熔断**：连败 3 → 该成员停 5 分钟，流量自动摊向其余成员；5 分钟后自动试探恢复
7. **全池灭**：行为 = 纯账号（兜底链照旧），恢复点由各成员熔断定时器唤醒

## 实施项（总 ~7.5h）

1. **内置供给**（~1h）：写一次性脚本把 3 个 js 压成 `gz_` 前缀 base64（同 config/index.ts 现有模式），追加 `user_api_builtin_{changqing,huanyin,qdy}` 三条目（name/version 取自脚本头注释）；`.scratch/source-pool/scripts/` 快照留档
2. **主进程池化**（~3h，主要风险点）：`userApi/spillChannel.ts` 单例窗口 → 成员注册表 `Map<memberId, {win, pendingInit, requestQueue, timeouts, lastUsedAt}>`；scope 标签 `--lx-spill-channel` → `--lx-spill-channel=<memberId>`（preload 透传，init/response 按成员路由）；成员 init 成功后上报平台×音质能力表（事件推给渲染层）；空闲 10 分钟销毁定时器；IPC `account_source_spill_url` 参数加 `memberId`
3. **渲染层池**（~2.5h）：`store/download/spillChannel.ts` 单成员状态 → 成员状态机 `Map<memberId, {chain, lastRequestAt, failCount, brokenUntil, inFlight}>` + 能力表（内置静态 + 动态 init 上报合并）；选择 = 能力过滤 + 最少在途；`action.ts` 的 `attemptSpill` 推广为 `attemptPool`（≤2 次）与兜底链跳过已试成员；任务状态文本/徽标参数化成员名（`metadata.sourceChannel` 存成员名，野花沿用旧值兼容已持久化任务）；熔断恢复唤醒定时器按成员
4. **验证**（~1h）：typecheck（双端）+ 真机验收

## 验收标准

1. 大批量 128k：解析交错放量于多个成员（日志可见成员名与各自 2s 节奏），同空闲仍优先账号
2. 毒成员测试：导入一个必然失败的脚本入池 → 连败 3 次后熔断 5 分钟，流量摊向其余成员，5 分钟后自动试探
3. 全池毒化：所有池成员不可用 → 行为等于纯账号 + 兜底链，任务不无限空转（恢复点可唤醒）
4. flac/320k 任务任何情况下不进池；播放不走池
5. 导入/删除自定义源 → 池成员即时增减；删内置源后重启复原
6. 幻音不接 kg 任务（能力过滤生效）；kw 任务可分到野草
7. 徽标显示实际成员名；旧任务里的「野花」标注不受影响
8. 空闲 10 分钟后沙箱窗口归零（任务管理器可见内存回落）
