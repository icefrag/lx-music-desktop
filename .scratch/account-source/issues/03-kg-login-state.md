# 03 - 酷狗登录态误报：启动提示退出登录，重登页面已登录但状态仍显示未登录

Status: ready-for-agent
Category: bug

## 现象（报告人自述，2026-10-14）

1. 正式版（v2.12.6 x64）启动时提示酷狗音源「退出了登录」
2. 点重新登录：登录页网页本身显示已登录状态，窗口很快自动关闭
3. 关闭后状态仍然显示「未登录」

## 已查证的事实

- dev 环境**未能复现**：同代码下 kg 启动校验通过（`validate(songinfo) -> status=1 err=0`）、取链正常带账号出链接。dev 与正式版的 cookie 分区数据是隔离的，疑似正式版分区的 cookie 形态不同（匿名 KuGoo / 缺独立 t 等）
- 正式版文件日志（electron-log）**没有账号音源记录**——该链路全走 console.log，未接入 electron-log，事件现场无证据
- 代码链路追踪（commit 41c80152 的 KuGoo 复合 cookie 新逻辑）有三个候选断点，无法从现有证据定死：
  1. **启动判定**：`hasLoginCookie` 依赖 `checkLoginCookieValue` 过滤匿名 KuGoo——若过滤误伤真实凭证 → login:false → 徽标「未登录」，且跳过启动校验
  2. **登录窗收尾竞态**：窗口自动关闭若走 `closed` 事件而非 settle 收网，`login()` 以「登录窗口已关闭」拒绝（渲染层对该文案静默）→ `validateAndUpdate` 从未执行 → 状态维持原样
  3. **登录后校验失败**：探针取凭证 `parseKuGooCookie(KuGoo).t` 与独立 `t` cookie 的兜底判断，若分区 cookie 形态与 dev 不同 → 校验失败 → 状态回到 unknown/expired
- 反证：同分区下 kg 取链全程正常（token 有效、直链带账号 id），说明「服务端认为凭证有效」与「应用判定未登录」并存，问题在本地 cookie 读取/判定层

## 已采取的措施（2026-10-14）

登录路径补了 3 处诊断日志（console.log，dev 控制台可见，稳定后移除）：
- `loginWin.ts` settle：捕获到的 cookie 名
- `loginWin.ts` cancelPending：登录流程结束原因（含「已关闭」竞态）
- `index.ts` initStatus：启动时各平台 login 判定结果；login()：登录后校验结果

## 诊断结论（2026-10-14 15:40，客户机 main.log 铁证）

```
15:33:53  启动判定 login=true                                  ← cookie 捕获/判定正常（KuGoo.tLen=64 有 token）
15:33:53  cookies: KuGoo.KugooID=1088523363 | 独立t=87c4c0**      ← 凭证完整
15:33:53  validate(songinfo) -> status=0 err=30020              ← web 探针被服务端拒绝
15:34:11  登录窗捕获 cookie: KuGoo（页面识别站点会话，秒关，未真正重新认证）
15:34:12  validate(songinfo) -> status=0 err=30020              ← token 未变，仍被拒
15:34:12  登录完成: login=true status=expired 凭证已失效
```

**根因两层**：
1. **服务端拒绝**：酷狗 web 校验接口对现存 token 返回 30020（同账号同代码在 dev 机器 err=0，差异为 mid/dfid 设备标识或 IP）——「退出登录」提示是如实报告
2. **假重登陷阱（UX bug）**：登录页识别站点会话即自动收网秒关，用户永远走不到「退出/重新认证」→ 重登无限循环无效

**附带发现**：正式版文件日志原本无账号音源记录 → 已接入 electron-log 双写（8803e3da）

**修复（8a90e88a）**：重新登录走强制认证——非 ok 状态下点「登录」打开的窗口**不再自动收网**（跳过 did-finish-load 检测与 cookie watch），用户在页面上完成退出/重新认证后**手动关窗**，关窗后一律执行 `validateAndUpdate` 刷新真实状态

**遗留跟进**：若强制真重登后探针仍 30020 → token 与设备参数（mid/dfid）绑定问题，需要给校验换通道（用取链同款移动端接口复核）再做一轮
