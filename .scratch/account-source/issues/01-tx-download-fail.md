# 01 - QQ 音乐（tx）下载重试失败

Status: closed (fixed)
Category: bug

## 现象

- 任务：千年泪 (穿越千年的眼泪只有梦里看得见) - Shake9（tx 源，128k）
- 用户在下载列表点重试，仍报「获取音乐链接失败」
- 时间：2026-10-13 晚（账号音源 ae12285f 合入后）

## 根因（抓包定位）

tx resolver 首版抄的是网页明文 `u.y.qq.com/cgi-bin/musicu.fcg` 通道。真机日志显示链路本身是通的（QQ 已登录、请求发出），但 GetVkey 模块恒报 `req_1.code: 500003 (subcode 860100001)`——该明文通道已被腾讯限制。

在 tx 登录分区挂 `webRequest` 抓包并让用户在调试窗口播放同一首歌，抓到网页播放器的真实取链请求：

- 端点：`u6.y.qq.com/cgi-bin/musics.fcg?sign=zzc...`（**移动端协议 + zzc 签名**，请求体加密 `encoding=ag-1`）
- cookie 关键字段：`uin`（无 o 前缀）、`qm_keyst`、`qqmusic_key`（与 qm_keyst 同值）

即登录态没问题，是**通道选错**（与酷狗 20018 同类教训：凭证平台与通道协议必须匹配）。

## 修复

`resolvers/tx.ts` 切换到移动端通道：`musics.fcg` + `zzcSign`（SHA1 派生签名，复刻自本仓库 `musicSdk/tx/utils/crypto.js`，纯 node:crypto 实现）+ UA `QQMusic 14090508(android 12)` + 完整分区 cookie（携带 qm_keyst/uin 登录态）。请求体为明文 JSON（`zzcSign(JSON.stringify(body))` 挂 query `sign`），响应结构与原解析一致（`req_1.data.midurlinfo[].purl`）。

用户真机重试验证通过（2026-10-13）。

## 复用结论

- 分区抓包对照法第二次命中（ADR-0003 方法论）：登录态类失败优先怀疑「凭证平台 × 通道协议」错配，先抓官方前端真实请求再改代码。
- zzc 签名可从 `musicSdk/tx/utils/crypto.js` 直接移植（纯 node:crypto，无浏览器依赖）。
